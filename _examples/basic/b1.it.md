Questo esempio riproduce l'[esempio base B1 di Geant4][example]. Utilizza la digitizzazione %%dosimeter%%
per memorizzare la dose accumulata in un rivelatore.

## Avvio rapido

Copia l'esempio nella directory corrente.
Per creare la geometria, simulare 10 eventi e produrre file di output ROOT e CSV:

```shell
cp -r $GEMC_HOME/examples/basic/b1 .
cd b1
./b1.py
gemc b1.yaml -n=10
```

<br/>

## Geometria
La geometria, mostrata di seguito, è definita in `b1.py`. 

Il volume mondo (un parallelepipedo chiamato %%root%%) contiene: 

- %%Envelope%%, un altro parallelepipedo costituito da acqua.
- %%Shape1%% e %%Shape2%%, un policono e un trapezoide, posizionati all'interno di %%Envelope%%. Sono costituiti
  da materiali che simulano tessuti e ossa, comuni nelle applicazioni mediche e quindi predefiniti nel
  [database dei materiali di Geant4](https://geant4.web.cern.ch/documentation/dev/bfad_html/ForApplicationDevelopers/Appendix/materialNames.html#):

  - G4_A-150_TISSUE
  - G4_BONE_COMPACT_ICRU

## Generatore

La cinematica delle particelle è definita nel file YAML:

```yaml
gparticle:
  - name: gamma
    p: 6*MeV
    vz: -15*cm
    delta_vx: 4*cm
    delta_vy: 4*cm
    multiplicity: 1
```

## Digitizzazione

La sensibilità del volume %%Shape2%% è specificata tramite la digitizzazione %%dosimeter%%
(una delle routine predefinite disponibili in GEMC) in `b1.py`:

```python
gvolume.digitization = 'dosimeter'
gvolume.set_identifier('mydosimeter', 1)
```

La digitizzazione %%dosimeter%% crea e accumula le variabili %%etot%% e %%dose%% nel corso degli eventi di un run.

$$
\mathrm{dose} = \frac{\mathrm{etot}}{\mathrm{mass}}
$$

dove %%etot%% è l'energia totale depositata in ciascun evento e %%mass%% è la massa di %%Shape2%%.

Qui, la stringa personalizzata %%mydosimeter%% e il numero %%1%% identificano l'elemento sensibile.

Le variabili %%mydosimeter%%, %%etot%% e %%dose%% vengono salvate nell'output.

Per ulteriori informazioni, consulta la [documentazione del dosimetro]( /home/documentation/sensitivity/dosimeter ).

## Utilizzo

### Costruzione del rivelatore

Usa lo script Python `b1.py` per costruire il rivelatore. Per impostazione predefinita, la configurazione
viene memorizzata in un file SQLite chiamato `gemc.db`. Le opzioni da riga di comando permettono di definire
il tipo di database, le varianti e il numero di run.

{% include notes/python-api-note.md %}

Per ulteriori informazioni, consulta anche [Costruzione della geometria]( /home/documentation/geometry/geometry_building ).


<br/>

### Esecuzione di GEMC

Il file `b1.yaml` può essere utilizzato per eseguire la simulazione con questa configurazione.
Aggiungi `-gui` per eseguire GEMC in modo interattivo:

```shell
gemc b1.yaml -gui
```

Le annotazioni e le decorazioni della scena sono definite in `annotations.yaml`, così lo stesso esempio
può essere visualizzato con o senza etichette:

```shell
gemc b1.yaml
gemc b1.yaml annotations.yaml
```

Modifica `b1.yaml` o la riga di comando secondo necessità, in particolare per aggiungere particelle,
controllare il numero di thread o cambiare l'output.

## Output

L'opzione %%gstreamer%% seleziona il nome e il formato dell'output. Il file YAML scrive simultaneamente
flussi CSV e ROOT:

```yaml
gstreamer:
  - format: csv
    filename: b1
```

{% include notes/output-note.md %}

Per ulteriori informazioni, consulta anche la [documentazione dell'output]( /home/documentation/output ).

## Creazione di grafici con GEMC Analyzer

Esegui prima GEMC con 20 eventi. Il file YAML predefinito scrive i flussi CSV per l'analizzatore.

```shell
gemc b1.yaml -n=20
```

Traccia il grafico della dose accumulata:

```shell
gemc-analyzer b1_digitized.csv dose --kind csv
```
