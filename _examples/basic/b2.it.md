## Avvio rapido

Copia l'esempio nella directory corrente.
Per creare la geometria, eseguire 10 eventi e produrre file di output ROOT e CSV:

```shell
cp -r $GEMC_HOME/examples/basic/b2 .
cd b2
./b2.py
gemc b2.yaml -n=10
```

<br/>

## Geometria

La geometria, mostrata di seguito, è definita in `b2.py`.

Il mondo (un parallelepipedo denominato %%root%%) contiene:

- %%target%%, un bersaglio cilindrico in piombo (%%G4_Pb%%)
- %%tracker%%, un contenitore cilindrico in aria (%%G4_AIR%%)
- cinque volumi cilindrici delle camere denominati da %%chamber_0%% a %%chamber_4%%, in xeno (%%G4_Xe%%) e collocati all'interno di %%tracker%% con dimensioni trasversali crescenti

## Generatore

La cinematica delle particelle è definita nel file YAML:

```yaml
gparticle:
  - name: proton
    p: 3000*MeV
    vz: -250*cm
```

Consulta anche la [Documentazione del generatore interno]( /home/documentation/generator/internal )

## Digitizzazione

La sensibilità dei volumi delle camere è specificata con la digitizzazione %%flux%%
(una delle routine predefinite disponibili in GEMC) in `b2.py`. Il numero di copia identifica ciascuna camera:

```python
gvolume.digitization = 'flux'
gvolume.set_identifier('mychamber', copyNo)
```

In questo caso, l'%%identifier%% contiene un solo nome: %%mychamber%%.

Consulta la [Documentazione di Flux]( /home/documentation/sensitivity/flux ) per maggiori informazioni.

Oltre alle variabili digitizzate, le informazioni vere vengono salvate nel flusso di output.

{% include notes/true_info-note.md %}

## Utilizzo

### Costruzione del rivelatore

Usa lo script Python `b2.py` per costruire il rivelatore. Per impostazione predefinita, la configurazione
è memorizzata in un file SQLite denominato `gemc.db`. Le opzioni da riga di comando consentono di definire
il tipo di database, le varianti e il numero di run.

Consulta anche la [Costruzione della geometria]( /home/documentation/geometry/geometry_building )
per maggiori informazioni.

<br/>

### Esecuzione di GEMC

Il file `b2.yaml` può essere utilizzato per eseguire la configurazione.
Aggiungi `-gui` per eseguire in modalità interattiva:

```shell
gemc b2.yaml -gui
```

Modifica `b2.yaml` secondo necessità, in particolare per aggiungere particelle,
controllare il numero di thread o cambiare l'output.

## Output

L'opzione %%gstreamer%% seleziona i nomi dei file di output e il formato:

```yaml
gstreamer:
  - format: csv
    filename: b2
```

Poiché %%flux%% è una digitizzazione per evento, GEMC produrrà un file di output per ciascun thread.
Per i file ROOT, puoi usare `hadd` per unire i file.

Consulta anche la [Documentazione dell'output]( /home/documentation/output ) per maggiori informazioni.

## Creazione di grafici con GEMC Analyzer

Esegui prima GEMC con 1.000 eventi. Il file YAML predefinito scrive i flussi CSV dell'analizzatore.

```shell
gemc b2.yaml -n=1000
```

Traccia l'energia totale depositata per hit:

```shell
gemc-analyzer b2_t0_digitized.csv totEdep --kind csv
```

![Energia totale depositata per hit nell'esempio b2][b2-analyzer_totEdep]{:width="70%"}

[b2-analyzer_totEdep]: /home/assets/images/examples/b2/analyzer_totEdep.png

Traccia l'energia vera della traccia della particella:

```shell
gemc-analyzer b2_t0_true_info.csv E --kind csv --data true_info
```

![Energia vera della traccia della particella nell'esempio b2][b2-analyzer_true_energy]{:width="70%"}

[b2-analyzer_true_energy]: /home/assets/images/examples/b2/analyzer_true_energy.png

Traccia il residuo dell'angolo polare del protone:

L'opzione `save_original_track: true` in `b2.yaml` salva %%otid%% e le componenti originali dell'impulso %%opx%%,
%%opy%% e %%opz%% nell'output delle informazioni vere. L'analizzatore usa le direzioni dell'impulso originale e
corrente per calcolare %%delta_theta%%.

```shell
gemc-analyzer b2_t0_true_info.csv delta_theta --kind csv --data true_info --pid 2212 --bins 100 --xlim -0.02 \
  0.2 --linear-y
```
