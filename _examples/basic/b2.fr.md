## Démarrage rapide

Copiez l'exemple dans votre répertoire courant.
Pour créer la géométrie, exécuter 10 événements et produire des fichiers de sortie ROOT et CSV :

```shell
cp -r $GEMC_HOME/examples/basic/b2 .
cd b2
./b2.py
gemc b2.yaml -n=10
```

<br/>

## Géométrie

La géométrie, illustrée ci-dessous, est définie dans `b2.py`.

Le monde (une boîte nommée %%root%%) contient :

- %%target%%, une cible cylindrique en plomb (%%G4_Pb%%)
- %%tracker%%, un conteneur cylindrique constitué d'air (%%G4_AIR%%)
- cinq volumes de chambre cylindriques nommés %%chamber_0%% à %%chamber_4%%, en xénon (%%G4_Xe%%) et placés à l'intérieur de %%tracker%% avec une taille transversale croissante

La cinématique des particules est définie dans le fichier YAML :

```yaml
gparticle:
  - name: proton
    p: 3000*MeV
    vz: -250*cm
```

## Numérisation

La sensibilité des volumes des chambres est définie avec la numérisation %%flux%% (l'une des routines prédéfinies disponibles dans GEMC)
dans `b2.py`. Le numéro de copie identifie chaque chambre :

```python
gvolume.digitization = 'flux'
gvolume.set_identifier('mychamber', copyNo)
```

Dans ce cas, %%identifier%% ne contient qu'un seul nom : %%mychamber%%.

Consultez la [documentation de Flux]( /home/documentation/sensitivity/flux ) pour plus d'informations.

En plus des variables numérisées, les informations vraies sont enregistrées dans le flux de sortie.

{% include notes/true_info-note.md %}

## Utilisation

### Construction du détecteur

Utilisez le script Python `b2.py` pour construire le détecteur. Par défaut, la configuration est stockée dans un fichier SQLite
nommé `gemc.db`. Des options en ligne de commande permettent de définir le type de base de données, les variations et le numéro de run.

Consultez également la page [Construction de la géométrie]( /home/documentation/geometry/geometry_building ) pour plus d'informations.

<br/>

### Exécution de GEMC

Le fichier `b2.yaml` peut être utilisé pour exécuter la configuration. Ajoutez `-gui` pour l'exécuter de façon interactive :

```shell
gemc b2.yaml -gui
```

Modifiez `b2.yaml` selon vos besoins, en particulier pour ajouter des particules, contrôler le nombre de threads ou modifier la sortie.

## Sortie

L'option %%gstreamer%% sélectionne les noms des fichiers de sortie et le format :

```yaml
gstreamer:
  - format: csv
    filename: b2
```

Comme %%flux%% est une numérisation par événement, GEMC produira un fichier de sortie par thread.
Pour les fichiers ROOT, vous pouvez utiliser `hadd` pour fusionner les fichiers.

Consultez également la [documentation sur la sortie]( /home/documentation/output ) pour plus d'informations.


<br/>

## Tracé avec l'analyseur GEMC

Exécutez d'abord GEMC avec 1 000 événements. Le fichier YAML par défaut écrit les flux CSV de l'analyseur.

```shell
gemc b2.yaml -n=1000
```

Tracez l'énergie totale déposée par impact :

```shell
gemc-analyzer b2_t0_digitized.csv totEdep --kind csv
```

![b2 : énergie totale déposée par impact][b2-analyzer_totEdep]{:width="70%"}

[b2-analyzer_totEdep]: /home/assets/images/examples/b2/analyzer_totEdep.png

Tracez l'énergie vraie associée à la trajectoire de la particule :

```shell
gemc-analyzer b2_t0_true_info.csv E --kind csv --data true_info
```

![b2 : énergie vraie associée à la trajectoire de la particule][b2-analyzer_true_energy]{:width="70%"}

[b2-analyzer_true_energy]: /home/assets/images/examples/b2/analyzer_true_energy.png

Tracez le résidu de l'angle polaire du proton :

L'option `save_original_track: true` dans `b2.yaml` enregistre %%otid%% et les composantes de l'impulsion initiale %%opx%%,
%%opy%% et %%opz%% dans la sortie des informations vraies. L'analyseur utilise les directions initiale et actuelle
de l'impulsion pour calculer %%delta_theta%%.

```shell
gemc-analyzer b2_t0_true_info.csv delta_theta --kind csv --data true_info --pid 2212 --bins 100 --xlim -0.02 \
  0.2 --linear-y
```

![b2 : résidu de l'angle polaire du proton][b2-analyzer_delta_theta]{:width="70%"}
